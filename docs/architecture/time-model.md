# 时间同步与关联

## 三种独立验收对象

时钟对齐、相机曝光同步、多源数据关联分别验收。时间戳相同不能证明同时曝光；NTP/Chrony 或 Wi-Fi TSF 测量不能替代曝光验证。

每项需求须登记目标、测量方法、统计窗口、p95/p99/最大误差和失锁容忍时间。单机五路曝光、视频与 IMU、视频与音频、跨设备时间分别登记。当前精度阈值未确认，生产任务不得将未配置阈值解释为零误差或无限容忍。

## 时间戳模型

公共结构见 include/common/timestamp.h。source_id 在任务清单中唯一对应物理时钟；同类传感器也可能拥有独立时钟。raw_ticks 保留原始计数，tick_hz 描述计数频率，sequence 表示流内序号；不可用字段由 flags 表达。common_ns 是任务共同时间轴，只有映射有效时才能使用。error_bound_ns 是误差估计边界，不代表已通过硬件验收。

传感器时钟扩展回绕前须知道计数位宽和最大采样间隔；无法消歧时开启新 epoch。设备重置、主机重启和同步源切换创建新 epoch，禁止跨 epoch 直接插值。CLOCK_REALTIME 仅用于墙钟标记，持续时间及超时使用单调时钟。共同时间轴以任务指定的主机单调域为基准，跨主机另保存映射关系。

映射采用分段仿射关系 common_ns = a × raw_ticks + b，记录版本、有效区间、拟合样本、残差和误差估计。旧映射不可被静默覆盖；离线重算须生成新版本并保留采集时结果。

## 事件和关联

帧索引保留原始时间、序号、可用时的触发编号及曝光语义（开始/中心/结束/未知）。驱动交付时间单独记录。IMU 必须区分 FIFO 读出时间与实际采样时间；音频记录块首样本时间、采样率、样本数量和 xrun。

关联窗口有上限；迟到、重复、缺失、超差均产生质量记录，不通过修改原始时间掩盖异常。同步状态为 UNKNOWN / ACQUIRING / LOCKED / HOLDOVER / LOST。进入 HOLDOVER 后误差边界随时间增长；达到任务阈值后由总控按策略停止或显式降级。
