# 运行架构与资源管理

状态：设计基线；五路性能、硬件同步精度和驱动能力尚未经过板端验收。

## 进程与依赖

第一阶段采用一个 capture-service 采集进程；MediaMTX 与上传 worker 独立运行。manager 是进程内模块，不是独立服务。当前尚无 capture-service 可执行程序。

控制流：API / 蓝牙适配器 → capture_manager → 业务模块。health_monitor 只上报事件，由总控决定恢复。common 不依赖业务模块。硬件驱动、设备树和 SDK 补丁在 SDK 仓库维护，发布时记录其版本。

数据流：camera_manager → encoder → storage_manager；编码输出另行分发至 streaming。IMU、音频和触发事件经过时间映射后写入 storage_manager。aligner 处理时间元数据和有限窗口的关联，不集中复制五路原始图像。时间映射不可用时保留原始数据并标记无效，不伪造同步时间。

## 线程与队列

总控线程串行处理命令和状态转换；设备读取线程不得执行网络、封装或文件同步操作。相机按设备拥有独立采集上下文。编码使用独立执行上下文，实际线程数量由 SDK 能力和实测决定。存储线程拥有封装器和文件句柄。预览、上传使用独立的有界队列。

每个队列必须配置容量、计量单位、最大等待时间和溢出策略；禁止无界增长。录像默认完整性优先：队列溢出上报 fatal，任务进入收尾并记录缺失区间；允许丢帧必须由显式任务策略启用。预览可丢弃积压数据，并从可解码关键帧恢复。上传限速及并发可配置，采集时优先让出资源。任何等待支持超时和取消。

## 缓冲区契约

驱动缓冲由采集模块拥有，交付对象携带释放回调和上下文；消费者持有期间不得归还 V4L2 队列。每份引用只释放一次，多消费者必须使用显式引用计数。回调在最后一个引用释放时执行，停止流程先排空引用再关闭设备。

DMA-BUF 是待验证的优化路径，不假定 V4L2、MPP 的格式、stride、缓存一致性或 fence 自动兼容。接口必须描述各 plane 的 fd、offset、stride、size 和同步责任。不支持导入时使用有界复制路径并报告复制量。码流录像和预览共享不可变数据，慢预览不得延长采集缓冲生命周期。

## 资源预算

五路 1920×1200、30 fps、紧密排列 NV12 原始数据约 518.4 MB/s；每路六帧约 103.68 MB。实际按驱动 sizeimage、stride、编码缓冲与 ISP 开销核算。存储预算为各路码率之和 / 8，加音频、IMU、索引和安全余量；容量按最长任务时长计算。

上线前测量五路采集/编码吞吐、CPU、RSS、温度、队列峰值、磁盘持续写速和 fsync 延迟。板端配置在能力探测通过后才能进入 READY，不能仅凭目标分辨率承诺运行能力。
